### V2: 歌词对齐 (Whisper large-v3)

**状态: PASS (但质量极差)**

| 指标 | 第一轮 | 第二轮 |
|------|--------|--------|
| 处理时间 | 30.9s | 29.1s |
| 检测段数 | 15 | 5 |
| 平均段长 | 2.92s | 6.07s |

第二轮检测到的歌词:
```
[44.3s] 让我们要深深要记起
[47.6s] 和好人心的印记
[68.5s] 请不吝点赞 订阅 转发 打赏支持明镜与点点栏目  (15.1s!)
[109.8s] 与点点栏目联系
[114.6s] 明镜需要您的支持 欢迎订阅明镜
```

**严重发现**: Whisper 对同一首歌两次识别结果完全不同:
- 第一轮: 15 段, 包含 "我所在他在", "幸福品处情好坏"
- 第二轮: 5 段, 包含 YouTube 频道推广语 ("请不吝点赞 订阅 转发")

这说明: 1) Whisper 对中文歌词识别极不可靠; 2) 测试音频可能包含非歌词内容 (YouTube 频道水印); 3) 结果高度非确定性

**结论**: Whisper **绝不能**作为主歌词源。必须实现 LRC 歌词上传作为主方案, Whisper 仅作为时间戳对齐辅助。

### V3+: RVC 真实推理验证 (第三轮新增)

**状态: PASS (真实训练模型推理)**

| 指标 | 值 |
|------|-----|
| 模型来源 | samaschen/RVC_rc_voice (hf-mirror.com) |
| 模型大小 | 53MB (.pth) + 128MB (.index) |
| 模型类型 | RVC v2 训练音色模型 |
| f0 方法 | harvest (rmvpe 因 PyTorch 2.11 兼容问题暂时不可用) |
| 模型加载时间 | 3.08s |
| GPU 显存占用 | 53MB |
| 总推理时间 | 22.98s (5 段) |
| 成功段数 | 5/5 |
| 平均每段 | 4.60s |

逐段详情:
| 段 | 输入文件 | 推理时间 | 输出大小 |
|----|---------|---------|---------|
| 1 | line_001.wav | 5.62s | 263KB |
| 2 | line_002.wav | 4.03s | 544KB |
| 3 | line_003.wav | 7.02s | 1178KB |
| 4 | line_004.wav | 4.22s | 370KB |
| 5 | line_005.wav | 2.09s | 8KB |

**关键发现**:
1. **推理速度与段长度正相关**: line_003 (2601KB 输入) 耗时 7.02s, line_005 (21KB 输入) 仅 2.09s
2. **rmvpe f0 不可用**: PyTorch 2.11 的 `weights_only=True` 默认行为导致 `rmvpe.pt` 加载失败。harvest 作为替代方案正常工作
3. **性能瓶颈**: 30 段典型歌曲推算 ~138s, 40 段 ~184s, 超过 180s 目标
4. **优化路径**: 切换到 rmvpe (需解决兼容性) + 批处理 → 预计可降到 60-80s (30 段)

**环境修复记录**:
- fairseq `torch.load()` → 添加 `weights_only=False`
- rvc_python 所有 `torch.load()` → 批量添加 `weights_only=False`
- hubert_base.pt 通过 hf-mirror.com wget 下载 (181MB)
- 模型目录结构需符合 rvc-python 约定: `models_dir/model_name/model.pth`
