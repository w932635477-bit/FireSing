## 背景

基于 2026-04-15 Medvi 获客方法论研究（见 2026-04-15-medvi-acquisition-analysis.md、
2026-04-15-china-acquisition-playbook.md），我们寻找"低成本获客方法本身就是产品"的
切入点。

核心发现：Medvi 式矩阵号运营者用 AI 批量生产视频内容，但面临两个问题——
AI 生成内容有明显的"塑料感"，且多条视频看起来雷同，无法通过平台重复内容检测。

抖音案例验证：账号"威纳Way"（6638 粉丝）发布的"4步去除AI塑料味儿"视频
获得 3.2 万点赞、4026 条评论，证明这是一个被广泛认可的痛点。

---

## 一、产品定位

**一句话：让 50 条 AI 视频看起来像 50 个不同的人用 50 台不同的设备拍的。**

不是"去 AI 塑料感工具"（会被大模型升级吞掉），而是
"AI 视频批量风格化工作流"（持久需求，解决批量差异化问题）。

### 定位分析

| 层级 | 谁在做 | 可持续性 |
|------|--------|---------|
| AI 视频生成 | Sora/Kling/可灵/Runway | 大模型核心业务，持续投入 |
| 单条视频去 AI 感 | 大模型自身在改善 | 12-18 个月内会被模型升级解决 |
| **批量后处理 + 风格差异化** | **目前没人做好** | **持久需求，工作流问题不是模型问题** |
| **参考风格匹配工作流** | **目前没人做好** | **持久需求，创意需求不会消失** |

### 为什么大模型不会解决批量差异化

大模型优化的是"单条视频的生成质量"。矩阵号运营者的问题不是"单条视频不够真"，
而是 50 条视频从同一个模型出来，即使每条都很"真实"，看起来也一样。
需要后处理给每条视频加上不同的"镜头风格"——不同的颗粒、色偏、暗角，
让 50 条视频看起来像 50 个不同的人拍的。这是后处理工作流，不是模型能力。

## 二、目标用户

### 核心用户：Medvi 式矩阵号运营者

- 用 AI 批量生产视频，在抖音/小红书/TikTok 多账号分发
- 每天 3-50 条视频的生产量
- 需要内容看起来真实，不能被一眼识别为 AI 生成
- 需要多条视频之间有视觉差异，避免平台判定为重复内容

### 用户画像

- 中国市场为主：抖音矩阵号运营者、小红书内容团队
- 海外市场（Phase 2）：TikTok 矩阵号运营者
- 行业：电商带货、知识付费、健康养生、本地生活等使用 AI 内容获客的商家

### 用户痛点

1. AI 生成视频有"塑料感"，一眼就能看出是 AI
2. 多条 AI 视频风格雷同，矩阵号内容被平台判定为低质重复
3. 手动在剪映里逐条加滤镜太耗时（50 条视频 × 3 分钟/条 = 2.5 小时）
4. 没有系统化的工作流把"AI 视频"变成"看起来真实的视频"

## 三、核心功能

### MVP（第一版，2 周内上线）

#### 功能 1：批量上传

- 支持一次拖入 10-50 条视频
- 支持 MP4/MOV 格式
- 显示上传进度和预计处理时间

#### 功能 2：风格预设库

每种风格模拟一种真实拍摄设备/质感，基于物理光学特性：

| 风格名称 | 模拟目标 | 核心参数 |
|---------|---------|---------|
| 电影胶片 | 柯达/富士胶片 | 暖色偏移 + 有机颗粒 + 暗角 + 高光溢色 |
| 手机拍摄 | iPhone/安卓随手拍 | 自然色温 + 微抖动 + 偶尔失焦 + 数字噪声 |
| 纪录片 | 新闻纪实风格 | 冷色偏 + 粗颗粒 + 镜头呼吸 + 手持晃动 |
| 老式 DV | 90 年代家用录像 | 低分辨率感 + 强色偏 + 拖影 + 扫描线 |
| Vlog 风格 | 博主日常记录 | 明亮色调 + 轻颗粒 + 浅景深模糊 |
| 新闻采访 | 专业新闻画面 | 冷色调 + 高锐度 + 微暗角 + 偶尔晃动 |

#### 功能 3：自动差异化

同一批视频，每条自动应用不同的随机参数变异：

- 颗粒强度：基础值 ± 30%
- 色温偏移：基础值 ± 200K
- 暗角强度：基础值 ± 25%
- 镜头呼吸幅度：基础值 ± 40%
- 微抖动频率：基础值 ± 50%

确保同一批 50 条视频中没有任何两条完全一样。

#### 功能 4：一键批量导出

- 处理完成后打包下载（ZIP）
- 文件命名包含风格标识和序号
- 支持选择输出分辨率和格式

### 后续版本（MVP 验证后）

#### 功能 5：参考图风格匹配

- 上传一张参考图/视频帧
- 工具分析其风格参数（色调、颗粒、对比度、暗角）
- 自动生成匹配的预设并应用到批量视频

#### 功能 6：平台适配预设

针对不同平台的推荐偏好和压缩特性做优化：

| 平台 | 适配要点 |
|------|---------|
| 抖音 | 适应其 H.264 压缩，略微提高饱和度和对比度以对抗压缩损失 |
| 小红书 | 偏向明亮清新色调，适配其图片/短视频推荐偏好 |
| TikTok | 适配英文市场审美，更鲜明的色彩和动态 |

#### 功能 7：API 接口

- REST API 供其他工具/平台调用
- 实现全自动化：AI 生成 → 风格化 → 分发
- 按调用量计费

## 四、技术方案

### 后处理管线

```
输入视频 → [1.颗粒/噪点] → [2.色彩偏移(LUT)] → [3.暗角] → [4.光晕/溢色]
         → [5.镜头呼吸(微抖)] → [6.帧率抖动] → 输出视频
```

每步处理的参数从预设中读取，并在预设基础上叠加随机变异。

### 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后处理引擎 | Python + FFmpeg + OpenCV | FireSing 项目已积累的音视频处理经验 |
| 颗粒/噪点 | OpenCV 高斯噪声叠加 | 模拟传感器噪声 |
| 色彩偏移 | FFmpeg LUT 滤镜 / Color Matrix | 模拟不同胶片/相机的色彩科学 |
| 暗角 | FFmpeg vignette 滤镜 | 径向渐变暗化 |
| 光晕/溢色 | FFmpeg convolve / 自定义 shader | 高光区域扩散 |
| 镜头呼吸 | FFmpeg zoompan + 随机参数 | 微妙的缩放抖动 |
| 帧率抖动 | OpenCV 帧操作 | 偶尔插入微帧偏移 |
| 前端 | React/Next.js 或纯 HTML | 上传 → 选风格 → 下载 |
| 部署 | 前端 Vercel，后端 GPU 服务器 | AutoDL 服务器用于处理 |

### 处理速度要求

- 单条 15 秒视频处理时间：< 30 秒
- 批量 50 条视频处理时间：< 15 分钟
- 可通过并行处理（多 GPU / 多进程）加速

## 七、风险与应对

| 风险 | 严重程度 | 应对 |
|------|---------|------|
| 处理速度慢，用户流失 | 高 | 并行处理 + 预处理缓存 + 异步队列 |
| 风格质量不好，用户觉得"还不如不处理" | 高 | 精心调参每种预设，找真实影片做参考对比 |
| 用户觉得"剪映加个滤镜就行了" | 中 | 差异化在"批量"和"自动差异化"，不是单条处理 |
| 剪映/CapCut 加上类似功能 | 中 | 先发优势 + 专注极致 + API 集成能力 |
| 大模型 12-18 个月后减少塑料感 | 低 | 届时转向"电影感/胶片感风格平台"，创意需求持久 |
| 中国 AI 内容标注法规（2025.9 起） | 低 | 工具本身是后处理工具，不涉及内容标注合规 |
